# SteamSafe Beta v0.1.2.2 管理员修复版

本次新增：图形安装向导支持自定义本地安装目录、可选桌面快捷方式、开始菜单入口及 Windows 应用卸载入口。卸载默认保留设置、缓存和隔离备份。

沿用修复：未收录编号脚本仅记录为信息，不以未收录或普通核对项阻止受保护启动；所有脚本继续接受语义检查。高风险证据、可信文件不一致或检查未完成仍会阻断。目录确认前后台安静等待；安全复查通过且 Steam 已在运行时不重复启动。保留原有签名证书。SteamSafe 使用独立的数据目录和自启任务；从旧名称升级时先关闭旧版自启、退出旧版，再安装并重新确认 Steam 目录。旧版备份不会自动迁移或删除。

支持 Windows 10/11 x64 的 Steam 正式版，Python 实现，发行包内置解释器。交付为单个 `SteamSafe-v0.1.2.2-Beta-Setup.exe` 管理员安装器，使用 Windows 自带 .NET Framework 4.8。无需安装 Python。

安装包下载：[GitHub Releases](https://github.com/hoadl114514/SteamSafe/releases/tag/v0.1.2.2-beta)。这是私有仓库，需登录有访问权限的 GitHub 账号。

## 安装与升级

1. 先从托盘退出旧版本，并关闭旧的登录自启。
2. 运行 Setup.exe，允许 UAC。选择安装目录，可选择桌面快捷方式及安装后启动。安装器验证自身签名和内置发行载荷，创建受保护安装目录和开始菜单入口，并注册 Windows 应用卸载入口。默认安装在 Program Files；自定义目录及已有父目录必须由管理员控制，拒绝普通用户可改写的父目录、网络路径及重解析点。
3. 不要单独复制主 EXE 或把管理员目录版放在普通用户可写目录长期运行。安装目录／文件、私有数据目录只允许管理员和 SYSTEM 写入，存在重解析点或不可信 ACL 会拒绝使用。
4. 检查自动发现的 Steam 目录，执行“立即检查”。后台守护和自动隔离修复默认启用。
5. 在界面启用登录自启时创建最高权限计划任务；任务动作指向受保护 EXE，普通用户只有读取／运行权限，没有修改动作权限。仅支持同一管理员账号的桌面登录，跨账号 UAC 不支持此自启。

程序数据位于系统 ProgramData 下的 SteamSafeBeta-v0.1.2，管理员和 SYSTEM 可访问。不会自动采用旧版普通用户可修改的缓存／修复日志。Steam 和官方帮助浏览器通过桌面用户令牌启动，避免继承守护程序的管理员权限。

## 新增检测

- HTML、CSS、JS/MJS、DLL/DRV、EXE、CFG 的 Windows 文件变化通知；独立守护线程约每 0.5 秒检查进程，不被网络下载阻塞。
- 既有敏感目录 DLL 侧载、versionOrg 转发结构、配置值、客服路由、假告警和启动项检查。
- 新增界面脚本与 HTML script src、JS 动态 import/导入的加载关系检查。未知脚本只作为线索；加载到非基线代码或强恶意语义时处理。
- URL／客服上下文的复制事件拦截、剪贴板清空／替换，与定时器及日期关联的延迟载荷检查。定时器本身不判恶意。
- 已确认高风险且非官方基线的 steamui/clientui 新增 JS/MJS，先备份再移除；修改的已知程序、JS/CSS/HTML 从对应版本的验证包恢复。游戏目录同名 MOD 不进入自动删除范围。
- 恢复后 5 分钟内再次出现异常，保持复发拦截；用户处理来源后可在界面复查并解除。
- 如果系统已经部署并配置 Sysmon，可读取近 5 分钟的 FileCreate/ProcessAccess 元数据作为来源线索。不安装 Sysmon，不读取或转储账号令牌，也不会据元数据猜测删除外部游戏／MOD。没有相关事件时明确报告无法归因。

脚本检查有大小／文件数限制，复杂混淆、运行时生成的代码不保证识别。未知域名和签名有效／无效都是证据的一部分，不等于完整病毒判定。主动安装的客户端插件可能触发严格规则。

## CDN 版本不一致的自动更新

1. 获得官方 HTTPS 清单，确认本地版本与目标不同后先结束 Steam。
2. 获取该版本的可信参考。更新启动器或依赖不可信时，不直接执行它：先从验证过的官方组件恢复。没有旧版可信参考时恢复受覆盖的最新客户端文件，再执行官方更新。
3. 使用安装目录的 steam.exe 并传入 -forcesteamupdate，以桌面用户身份启动。
4. 主动确认本地版本已经切换，连续三次文件快照稳定，新启动日志出现目标 installed version 与 Verification complete，最后完整哈希及安全复查通过。
5. 再次请求 CDN，避免更新过程中发布新版本却误报“已是最新”。目标又变化、网络错误或超时会报告未完成并结束 Steam。

窗口出现、下载完成、版本字符串单独一致均不能作为完成依据。等待上限默认 10 分钟。正常更新期间允许两份已验证版本的过渡资源，仍检查侧载／配置；最终只接受目标版本。持续发布或 CDN 缓存不一致可能需要再次检查。

断网时可以检查匹配的签名发行基线，但不会宣称已经确认最新版本。Win32、ARM64、Steam Beta、Steam China 的恢复暂未支持。

## 自签名与启动自检

主 EXE、计划任务组件、安装器使用自生成代码签名证书签署。主程序固定证书 SHA-256，启动时校验 Authenticode 和 Ed25519 签署的整个发行文件清单，拒绝文件变化、证书不符或额外程序文件。

自签名没有公共 CA 信任或 SmartScreen 信誉，Windows 仍可能显示未知发布者／不受信任证书。不自动导入 Root 或 TrustedPublisher。仅在证书指纹匹配、完整发行清单验证通过时接受预期的 untrusted-root 状态，其他签名错误拒绝运行。

自检是篡改检测，不是管理员／内核攻击下的自保护。篡改运行中的程序、绕过检查或已有同等权限的攻击者不在可靠保护边界内。私钥/PFX/口令只在维护者 .release-keys 目录中，永不进入安装器、源码包或已安装目录。

管理员版没有内核防注入驱动、PPL 或完整内存保护，不能保证拦截无文件注入、手动映射和凭据读取。已有 Sysmon 日志只提供部分历史证据。要可靠阻断进程内存访问，需要独立驱动与正式签名验证，不能用本证书代替 Windows 驱动发布签名。

## 隔离与账号恢复

异常后先结束 Steam、保留证据、隔离／恢复，再复查并警告。修复不自动表示感染来源清除或账号安全；如果载荷已经执行，请在可信设备处理密码、会话授权和登录记录。界面提供独立的固定官方安全帮助入口，不依赖受感染 Steam 中的链接或复制结果。

quarantine/old 保存原文件，journal.json 记录原、新哈希和状态。回滚必须退出 Steam，可能恢复危险文件；守护重新发现后会处理。实际来源无法确认或无权限修复时不猜测删除，维持拦截并报告。

不上传文件、账户或报告，不搜集账号令牌。URL 证据隐藏查询参数。日志和隔离资料可能仍包含本地路径及原恶意内容，只保留在受保护数据目录，分享前核对。

## 卸载与开发

从 Windows 设置的“已安装的应用”、开始菜单中的卸载入口或安装目录 Uninstall.exe 启动卸载。卸载器结束本目录的守护程序，移除指向本版本的自启任务、快捷方式、注册信息和发行文件，保留其他文件。默认保留隔离备份及程序数据；只有明确勾选清理并再次确认时才删除共享数据，多版本共存时禁止清理。正在运行的卸载器和最终空目录将在重启后清理，重启前不能复用该安装目录。旧版无卸载入口的版本须先关闭自启、退出后手动移除。

构建环境：Python 3.12 x64、requirements-build.txt、Windows SDK SignTool、.NET Framework C# 编译器。先创建 .venv 并安装 requirements-build.txt，然后执行 build.ps1；私钥必须保密。首次从 GitHub 源码构建时执行 build.ps1 -RefreshBaseline，生成你自己的基线签名密钥和代码签名证书；私钥未上传，不能直接复用发行者的签名。使用当前签名基线和证书，不自动修改系统信任库。测试只用模拟 Steam 安装，同代码 asInvoker 诊断副本执行自测和离屏 GUI；正式 EXE 的管理员清单与签名另行验证。

Windows UAC 安装、保护目录写入和计划任务实际注册应在受控机器验收；本工作区验证不会自动安装到本机、注册自启或更新用户实际 Steam。本版安装器验收范围见 QA-installer-v0.1.2.2.md；此前检测证据见 QA-report.md。
